# ResumaCAD

## 持续人机 CAD 编辑中的几何证据维护与可靠续作

Version-Aware Geometric Evidence for Reliable Continuation in Human-AI CAD Editing

**选题报告与预实验计划 | 2026-10-25 | v1.0**

> 核心问题：一个共享 CAD 项目已经被人或其他 agent 修改，AI 先前获得的哪些几何证据还能用于当前行动？能否只补充必要的新观测，就正确、低成本地继续设计？

ResumaCAD 取意于 resume，突出人机交替编辑后的可靠续作。本报告记录今天形成的研究决定，为后续协议设计、基线复现和方法实验提供共同起点。研究依托现有 DBCAD 几何与版本底座，计划形成两项相互独立、可检验的贡献：**持续编辑评测体系**与**版本感知的几何证据维护方法**。

### 决策摘要

- **研究对象**：经历需求更新、外部编辑、暂停/恢复和实体引用变化的共享三维 CAD 项目。先从零件与小装配、有限查询和操作范围开始。
- **研究动机**：历史观测可能失效；全部重读又会增加观测、上下文和验证开销。需要同时考察可靠性与成本。
- **拟定路线**：先构建中立协议和小型诊断，运行强基线，再决定方法；优先固定现有 VLM，不以训练新基础模型为起点。
- **当前状态**：原生底座、AI 编辑入口与既有单轮 harness 对照已经完成；新的持续编辑 benchmark、证据维护机制与其效果尚未实现或验证。
- **立项边界**：已有多轮 CAD、长时程 CAD、约束保持和 agent 记忆研究。本课题不以“首次长期 CAD”或“首次图记忆”为主张。

### 阅读路线

第 1-2 节说明问题和相关工作的边界；第 3 节说明现有基础；第 4-7 节定义目标、benchmark 和候选方法；第 8-9 节规定实验、指标和否证条件；第 10 节给出启动路径和预期成果；最后附参考文献与术语。

**证据口径**：文献结论来自论文或官方代码/规范的定向核对；本地结果来自既有实验报告和本轮代码/几何诊断；带“计划、候选、拟定”的内容均为待验证研究设计。定向检索不等于全领域系统综述，也不能证明未公开工作不存在。

## 1. 问题界定：设计变化后，旧判断何时还能用？

### 1.1 区分三种状态

**几何状态**是当前模型本身，包括实体、拓扑、尺寸和装配位置；**要求状态**是当前仍有效的设计要求，包括新要求取代旧要求的关系；**认知状态**是 AI 保留的观测、判断、目标绑定和未提交计划。研究关注三者在版本演化中的一致性。

几何内核能执行精确运算和检查部分几何合法性，但合法 B-Rep 不自动代表孔径正确、装配间隙合格或设计意图满足。历史测量曾经正确，也不自动代表它现在能作为行动依据。反过来，用户将孔径从 6 改为 8 是合法的新要求，应取代旧要求，不能被系统错误阻止。

### 1.2 一个贯穿报告的任务情境

下表是拟定的说明性场景，不是已完成的长期实验。单位、保护项与新要求应在真实任务中显式给出。

| 阶段 | 项目事件 | AI 需要处理的状态 |
| --- | --- | --- |
| v1 | AI 检查带孔底板和安装空间，记录当前孔径及无干涉结论 | 将观测绑定到该版本、实例、参考系和查询范围 |
| v2 | 人修改远处的线缆支架 | 判断是否真正影响现有证据，避免无谓全量重测 |
| v3 | 新要求扩大目标孔，取代原孔径要求 | 撤销旧尺寸事实的当前用途，并更新要求状态 |
| v4 | 人将另一零件移入原插入区域；AI 没有执行该操作 | 即使孔未变化，也重新检查区域无障碍判断 |
| v5 | AI 恢复工作，要求继续安装并保护现有支架 | 基于当前证据续作；必要时重新定位、测量或澄清冲突 |

### 1.3 五个必须分开的实验维度

| 维度 | 含义及控制方式 |
| --- | --- |
| 修订历史长度 | 项目经历多少次语义修改；增加无关版本时保持当前任务难度不变 |
| 需求与引用跨度 | 当前任务依赖多久以前的角色、决定或历史状态；不等于工具调用次数 |
| 外部变化 | 由人或其他 agent 产生的变化；所有方法获得相同通知与查询权限 |
| 几何规模与变更范围 | 组件/面数、关系耦合、局部与全局编辑；与历史长度分别变化 |
| 模型上下文长度 | 实际发送的历史/图像/token；允许系统检索、摘要和读取最新快照 |

**初期范围**：尺寸、距离阈值和指定区域干涉等可执行查询，以及原生工具能够稳定执行的编辑。大装配、自由曲面、通用自动合并和多人实时并发不是第一阶段同时承诺的目标。

## 2. 相关工作与启发：哪些部分已经被研究？

### 2.1 CAD 修改、长时程操作与约束保持

| 相关工作 | 已有覆盖、对我们的启发与区别 |
| --- | --- |
| mrCAD [1] | 2D CAD 多轮人类交流与修改，含 6,082 个游戏、15,163 个指令-执行轮次。启发是保留真实上下文引用与人类修订表达；它排除了“首次多轮 CAD”的主张。 |
| neuralCAD-Edit [2] | 专家提出 192 个多模态编辑请求并提供 384 个编辑。启发是编辑已有模型、使用真实请求而非仅从零生成；其请求级评价不能直接替代持续共享项目评价。 |
| AgenticCADedit [3] | 有状态工具调用、检查、渲染、撤销形成编辑闭环。可作为续作方法的宿主；已有状态性不代表已解决跨会话外部变化后的证据有效性。 |
| IterCAD [4] | 代码-执行-视觉反馈迭代，包含 200 个局部编辑测试任务。启发是几何反馈和逐步修正；一个目标内的修复轮次不等于多条独立需求的项目生命周期。 |
| CADWorld [5] | 200 个 FreeCAD 任务、11 类工程工作流；报告实验最大 100 GUI 步/任务，终态检查工程文件。启发是工程产物验收；“长时程 CAD benchmark”已经存在。 |
| HistCAD [6] | 显式建模约束，并在局部尺寸编辑后区分有效状态可达性与其他约束的保持。启发是目标项和保留项独立评价；建模 history 不自动等于人机交替提交的版本链。 |

这些工作说明，前沿已经覆盖生成、修改、修复、交互、工程工作流和约束。不能将研究背景写为“大家仍然只做自然语言生成”。更准确的定位是：在已具备这些能力的系统上，进一步研究变化后的证据如何支持持续行动。

### 2.2 从建模过程图与持续状态获得什么路线？

**TraceCAD [7]** 将需求、建模步骤、错误证据和结果保存为恢复状态，并进行依赖域内修复和技能复用。它提示我们将计划与依据关联，也意味着持久状态、局部修复和经验记忆不是独立新意。

**CADIR [8]** 记录操作、参数、约束与拓扑选择的 construction graph，支持图/子图检索和几何签名匹配。它提示使用结构化依赖；但 DBCAD 的几何快照图不能冒充建模过程图，实体匹配也不能凭空假设已解决。

**MUSE [9]** 在 3D 场景创作中维护场景记忆和保护集，并评测 50 条三阶段链，即一次构建加两次连续编辑。它提示跨轮状态与每轮重建可分离；连续编辑链本身也已经有近邻研究。

## 2. 相关工作与启发（续）：记忆的一致性不是新概念

### 2.3 通用 agent 与经典算法的直接近邻

| 工作 | 已有机制 | 对 ResumaCAD 的约束与启发 |
| --- | --- | --- |
| Concord [10] | 关联工具观测与可变来源，根据版本/范围检测失效，并刷新或抑制上下文 | 是最直接的通用近邻。必须比较合理的 CAD adapter；仅增加 CAD 接口不够。 |
| TRACE [11] | agent 返回变化后的共享状态时，处理显式/隐式失效并准入所需记忆 | 返回与记忆准入问题已经被定义；CAD 增量应体现在几何依据及实际收益。 |
| MemTX [12] | 带来源与有效性的记忆、事务暂存与提交、动作门控及级联修复 | 事务、依赖传播和行动前校验须作为已有思想，不应重新命名为原创。 |
| 经典几何/协作研究 [13][14] | 增量距离计算利用几何连续性；多用户 CAD 区分语法与语义冲突 | 空间索引、距离界和语义冲突都有基础。应比较这些简单而强的机制。 |

### 2.4 工程实现已经做到哪一步？

**ARK [15]** 已有项目隔离、跨会话本地记忆、语义检索和操作收据；其文档明确区分记忆修订与当前 CAD 几何权威。**lambdacad [16]** 会记录人的手工增删改，并在报告时重验标签实体是否存活；存活仍不等于旧尺寸或间隙成立。**AgentCAD [17]** 的官方规范包含 JSON 记忆、决策、预算上下文与受控写入。规范覆盖不等于已完成长期效果验证。

因此，“JSON + 图数据库 + 向量检索 + 版本号”不足以支撑本课题。图数据库是可替换的承载层，不应成为评分偏好或论文结论的前提。

### 2.5 本课题当前可以主张什么？

**候选测量缺口**：在所核对的 CAD 协议中，尚未看到专门统一评测“共享项目外部变化、历史几何证据有效性、要求更新与暂停后续作”的直接证据。应通过新协议分离这些因素，而非只延长现有动作链。

**候选方法增量**：从 CAD 查询与编辑中构造几何依赖和保守有效条件，覆盖实例/参考系、拓扑不确定性及区域否定查询中的潜在新对象，并连接到续作和重新规划。

**待确认的关键点**：合理的空间失效策略或 Concord CAD adapter 是否已经足够？如果答案是肯定的，应承认该结果，调整或停止复杂方法。文献未见直接评测，不自动证明问题在实践中频繁，也不证明候选方法有效。

## 3. 已有基础与证据：我们从哪里开始？

### 3.1 DBCAD 能提供的实验底座

当前系统以 C++ ACIS worker 执行几何命令；FastAPI 管理命令与版本；内容寻址资产库保存 SAT/GLB/graph；Neo4j 管理版本清单与实体投影。**SAT + 版本清单是权威状态，JSON 图是派生查询索引。** BFS 遍历和关系提取使拓扑可查询，但不自动恢复设计意图。

已有版本、不可变组件、实体内容键、候选血缘与隔离 AI 预览，使我们可以定位证据来源、追踪变化并重放诊断。当前 AI 应用严格核对 base_version；工具覆盖图元、变换、删除与布尔，尚不覆盖全部局部特征操作。

仍需补齐的能力包括类型化几何查询、实例/参考系绑定、来源与覆盖收据、保守失效、上下文重建和持续事件评测。当前实体键不包含完整关系邻域，后备血缘匹配按类型和出现顺序贪心配对，不能直接充当稳定语义身份保证。

### 3.3 已跑通的离线反例，不是方法性能

- **关系失效**：孔半径 6 mm 的底板不变，障碍物移入半径 5 mm 的规定插入区域，内核相交体积由 0 变为约 64 mm³。目标未变不代表区域无障碍判断仍成立。
- **命题与数值不同**：两个方块距离从 5 变为 5.5 mm。旧数值过期，但在已证明扰动不超过 0.5 mm 时，4.5 mm 下界仍可支持“距离至少 3 mm”。
- **对应不确定**：调用当前实体匹配函数，在两张平面重新编号并交换枚举顺序的合成输入上出现左右错配。它说明后备策略无身份保证，不是实际模型失配率。

## 4. 研究目标、问题与贡献边界

### 4.1 总体目标

构建一个可复现的持续 CAD 编辑研究环境，识别版本演化中证据失效导致的错误；提出可核验、可回退的证据维护机制，在保持任务可靠性的同时减少不必要的重新观测和上下文开销。第一阶段不训练新基础模型，也不将 ACIS 替换或图数据库性能优化当作主要创新。

| 研究问题 | 可检验的假设 | 可能否定该假设的结果 |
| --- | --- | --- |
| RQ1：问题有多普遍？ | 外部变化、引用变化和要求取代会增加旧证据误用，并影响续作 | 合理的最新状态基线已稳定解决，历史条件没有额外影响 |
| RQ2：几何机制是否必要？ | 查询级依赖及保守有效条件比粗粒度失效更好兼顾保留与防错 | AABB/组件失效或 Concord adapter 已解释全部收益 |
| RQ3：能否改善端到端表现？ | 维护收益超过构图、检索、重验和重新规划开销 | 仅少量内核查询变少，总费用/延迟和成功率无实质改善 |
| RQ4：能否迁移？ | 同一证据协议在不同 harness、模型及几何后端上仍有用 | 只在单一模板、单模型或刚体位移任务上有效 |

### 4.2 两项候选贡献，分别验收

**贡献 A：评测协议与数据。** 提供有版本事件和要求生命周期的项目任务、两种评测轨道、独立验收器、统一观测权限、可审计轨迹与强基线。评测应揭示已有任务分数无法区分的失效机制，并在未见项目上保持有效。

**贡献 B：几何证据维护方法。** 实现从查询与编辑到依赖/有效条件的机制，处理保留、撤销、重验和未知状态，并将结果接到持续编辑的上下文与行动检查。方法不能只在为自己设计的评分器上占优。

两者可以在同一篇论文中联合呈现，但不能互相充当真实性证明：benchmark 需要独立的任务与真值依据；方法需要胜过强对照并通过消融。新增 benchmark 并不自动保证新增方法具有足够贡献。

### 4.3 初期可控范围与后续扩展

初期支持三类命题：解析孔/局部尺寸、对象最小距离阈值、指定区域无干涉。对不支持的几何、歧义对应或不可证明的编辑影响返回未知并重验。尺寸识别、角色绑定和变更覆盖均要计入系统成本及失败率。

后续扩展包括更长历史、更大装配、复杂局部操作与人机交替修改的安全续作。通用分支合并、实时多写者、完整物理/制造可行性和大型模型训练，均需在核心假设成立后另行立项。

## 5. Benchmark 设计：评价持续项目，而非堆叠调用

### 5.1 一个项目任务包应包含什么？

| 对象 | 内容与可见性 |
| --- | --- |
| 初始状态 G0 | 可读取的 STEP/原生模型、单位、坐标系、初始版本和组件作用域 |
| 请求序列 U | 按阶段开放的新编辑目标、保护项和合理的历史引用；不提前展示未来请求 |
| 事件序列 E | 人工/其他 agent 的编辑、作者、版本、通知与暂停恢复时机 |
| 要求状态 R | 要求的生效、取代、撤销和关联对象；系统可见信息与隐藏验收标注明确分离 |
| 预算与接口 B | 所有方法同等的查询、版本访问、通知、操作和费用约束 |
| 独立评价器 J | 检查当前目标、仍有效保护项及冲突处置；不读取方法内部证书来决定对错 |

### 5.2 两条互补轨道

**轨道 A：固定检查点的证据诊断。** 从统一历史状态出发，让系统先获得一组观测，再注入受控变化，检查旧命题的准入、重验和保留。所有方法面对相同几何事实，便于因果定位；该轨道不代表完整长期编辑成功率。

**轨道 B：闭环持续编辑。** 下一阶段继承各方法实际产生的模型和历史，评估其完成任务、保护设计、发现失效和恢复的能力。外部变化由可应用的语义操作定义；不能在每阶段载入标准快照，覆盖被测系统之前的修改。

<!-- figure: benchmark -->

图 2. 闭环评测：请求与外部事件驱动同一被测项目演化；独立验收逐阶段记录目标、保护项、错误和成本。所有未来答案与标准修复过程对 agent 隐藏。

### 5.3 保证任务可执行与比较公平

外部操作需要明确附着条件、实体定位方式和失败策略。若被测模型已偏离到无法执行事件，应记录任务诱发失败或环境失败的类别，按预注册规则处理，不能为某方法临时重置或跳过。合法的要求更新不能被旧保护项阻止；确实不可同时满足的请求应允许澄清，同时统计过度拒绝。

所有方法可以读取当前模型、收到相同版本更新并调用相同查询。不能要求系统猜测不可观测的人工编辑，也不能只向候选方法提供标准实体绑定。长上下文策略、检索策略和每次重新测量策略都应有公平发挥空间。

## 6. 数据、场景与规模：从可诊断走向可信

### 6.1 第一批受控诊断

拟定从 20 个参数化场景构造六类变化，共 120 个变化后检查点。它用于验证评价器和失效机制，**不是 120 条已完成的长期项目链**，也不是论文级自然场景频率估计。数量可随先导结果调整。

| 变化类别 | 主要检验点 | 拟定检查点 |
| --- | --- | --- |
| 不相干区域修改 | 有效证据应保留，整项目失效是否过度重测 | 20 |
| 局部尺寸/几何修改 | 旧尺寸和相关推论不应继续使用 | 20 |
| 新增或移入障碍物 | 否定查询必须考虑原结果集外的潜在对象 | 20 |
| 局部/整体刚体变换 | 局部不变量和世界坐标关系要区分 | 20 |
| 重编号、分裂与合并 | 不确定对应不能静默继承旧判断 | 20 |
| 撤销/恢复、参考系或单位变化 | 正确版本绑定、换算与证据恢复 | 20 |

### 6.2 闭环项目链与难度控制

先做少量 5 阶段小装配，跑通继承、变更和验收；之后拟扩展到 20/50 阶段，并独立改变引用跨度、外部变动率、组件数和几何复杂度。全局编辑可能使大部分记忆失效，必须纳入压力测试，不能只选局部变化让复用天然占优。

场景至少包含安装孔与邻件间隙、安装区域被新增零件占据、阵列/支架位置调整和合法要求取代。自然语言既包含明确数值，也包含“上一版那个孔”等历史引用。对歧义和无解请求设置明确的评价规则。

### 6.3 数据来源、切分与真实性

先用具有解析真值的参数化几何校准评价器，再加入许可允许的外部 STEP 和人工设计的编辑序列；邀请熟悉 CAD 的人员检查任务合理性。脚本模拟的人类事件须标为模拟，不能称为真实协作用户实验。

训练/开发/测试按零件或装配家族切分，不让同模板不同尺寸随机落入两侧。保留未见形状和未见变化组合；开发集用于选规则，冻结测试集后不按候选方法失败案例反复修改评分标准。

公开包计划提供 STEP、事件描述、标注规范、开放查询与验收接口、数据来源和许可记录。OCP 参考后端用于低门槛复现，ACIS/DBCAD 用于另一后端验证；两者不能在主方法比较中随意混用而引入内核差异。

## 7. 候选方法：版本感知的几何证据维护

### 7.1 存储单位从“模型文本”变为“可检验命题”

几何快照、原始观测、当前有效命题和设计要求分别存储。JSON/图数据库负责索引与溯源，几何内核负责受支持查询的求值。原始观测保留为历史，不因上下文更新被改写成“当时测到新数值”。

| 证据字段 | 作用 |
| --- | --- |
| query / predicate | 类型化的可执行查询及比较条件，例如距离是否至少 3 mm |
| source / version | 项目、来源版本、组件/资产及查询提供者标识 |
| occurrence / binding | 实体实例、目标角色和对应依据；不能只依赖共享内容键 |
| frame / unit / tolerance | 局部或世界参考系、单位与内核公差 |
| result / witness | 原始数值或命题结果及见证；精确值与推得下界分开 |
| dependencies / domain | 实体、关系、空间查询域与潜在对象集合的依赖 |
| guard / coverage | 允许复用的保守条件，以及序列化/编辑影响覆盖是否完整 |
| status / provenance | 当前有效、失效、未知或仅历史记录，并说明原因与验证版本 |

### 7.2 从变化到行动的闭环

<!-- figure: method -->

图 3. 候选证据维护层。来源变化先进入有效性判断，必要时调用内核；只有当前任务所需的有效证据进入后续行动。最终提交仍校验版本。

1. **记录观测**：在一致版本上绑定实例、参考系、用途和依赖，不认证 LLM 自述。
2. **消费变化**：读取受控编辑收据和场景变化，校验新增、删除、改形、变换及回退的覆盖。
3. **判断有效性**：有保守依据才复用命题；需要精确值或覆盖不明时重验/返回未知。
4. **重建上下文**：提供当前有效证据和变化摘要，撤销失效依据对应的未提交计划。
5. **提交检查**：校验 head；需前移时在当前状态重放并重验，不能覆盖旧全量清单。

普通的来源关联、级联更新和提交检查并非原创。待研究的核心是 CAD 查询依赖与保守有效条件的构造，以及其相对通用 adapter 的增量价值。

## 7. 候选方法（续）：三类关键几何情形

### 7.3 命题可以有效，旧精确数值不能冒充当前值

设两个几何集合原最小距离为 d0；若已证明它们各自的 Hausdorff 变化界不超过 a、b，则可使用保守下界 d_new ≥ d0 - a - b。判断阈值为 tau 时，只有下界连同公差仍不小于 tau，才可维持相应安全命题。这个基本距离稳定性不是新定理。

例如 d0=5 mm，一方已知平移界为 0.5 mm，另一方不变，则 4.5 mm 下界足以支持“至少 3 mm”。系统只能呈现这一命题或下界，不能继续把 5 mm 标为当前测量。未知布尔编辑、无变化界或新增对象不能擅自套用刚体界。

### 7.4 否定空间查询要覆盖“原先没有的对象”

“区域 Q 内不存在障碍”依赖的是对候选对象的完整覆盖。只跟踪已经命中的对象会遗漏新增零件。拟用空间候选更新和保守包围域识别新进入者；只要覆盖或界无法确认，就重新执行精确查询。AABB 等简单空间机制必须作为强基线。

### 7.5 身份、参考系与要求生命周期

刚体移动通常不改变局部孔半径，却会改变世界位置或与其他零件的关系。相同几何属性不代表相同实例；split/merge 后的实体不能仅凭枚举号续接记忆。第一阶段优先使用明确操作来源和可验证绑定，遇到歧义就重定位/失效，不同时承担新的通用拓扑命名算法。

要求可以被新要求取代，证据也可以保持历史正确却失去当前用途。需要显式记录这两类生命周期，避免把旧要求当成“记忆必须保持”的永久约束。对受污染的推理后缀，优先从准入后的状态重建计划，不要求 LLM 自己猜哪些旧推理应作废。

### 7.6 技术落地顺序

| 步骤 | 实现位置与产出 |
| --- | --- |
| 先跑通开放原型 | 在现有 CadQuery/OCP 研究环境实现统一查询、事件和独立评价，先固定一个 harness |
| 定义中立证据协议 | 查询/版本/实例/单位/覆盖/有效性字段；依赖图存储与算法接口分离 |
| 接入 DBCAD | 通过原生 worker 增补测量；Python 网关只处理中立值，ACIS 仍只存在于 worker |
| 建立保守回退 | 投影不完整、实体对应未知或编辑不支持时重新查询；记录覆盖与重验成本 |
| 迁移与优化 | 核心假设成立后再增加第二模型/harness 和后端；最后才考虑学习式调度或策略训练 |

现有 /diff 的实体键集合与候选 DERIVED_FROM 只可提供线索，不足以直接认证全部几何影响。数据库去重和实体匹配修复属于必要工程，不自动构成新研究贡献。

## 8. 对比实验：证明收益来自哪里

### 8.1 主对照与上界

| 对照 | 目的及公平要求 |
| --- | --- |
| B0：最新模型 + 有效要求 + 按需新鲜查询 | 最重要的简单基线。允许充分读取当前状态，检验是否真的需要历史证据维护 |
| B1：追加历史、固定窗口或普通摘要/检索 | 比较上下文组织；给相同工具能力，并记录实际 token 与维护成本 |
| B2：组件哈希/实体内容键失效 | 测粗粒度与内容级复用；不将内容共享当实体身份真值 |
| B3：保守空间域与 AABB 依赖 | 强几何基线，必须监听新增/移入对象，不能故意限制为已知目标 |
| B4：Concord 的合理 CAD adapter | 对比通用来源失效框架。若放入相同 guard 后机制等价，应承认等价 |
| B5：TRACE 准入或 MUSE 式每轮重建适配 | 在核心诊断后按资源选择，明确适配细节，不冒称逐字复现原系统 |
| Oracle：正确有效性/目标绑定 | 只作可达上界和瓶颈诊断，不计作自动方法成绩 |

首轮拟沿用 **AgenticCADedit 式工具闭环 + Qwen3.6-27B + OCP 查询原型**，以复用已有环境；同一模型、编辑器和后端上只比较证据机制。新协议结果独立计分，不沿用旧单轮成绩。它是可用起点，不代表最强模型；API 别名也不证明与论文权重一致。离线通过后，再在第二 harness、第二模型、不同预算和 ACIS 适配上检查迁移；适配版须明确命名，付费执行另行核对预算。

### 8.2 必要消融

- 去掉空间否定依赖：是否在新增障碍时误用旧结论？
- 去掉保守几何界：是否退化为更多精确重验，影响总体代价？
- 去掉实例/参考系信息：是否出现错误绑定或错误不变量传播？
- 整组件依赖与查询级依赖：收益是否只来自更细的普通缓存？
- 同等上下文预算的普通压缩：是否只因文字少、图像少而获益？
- 去掉失效后的计划重建：仅更新观测能否阻止旧计划继续执行？

### 8.3 公平性与失效归因

固定请求、外部变化、可见信息、工具接口与验收；比较时记录模型实际版本、输出上限和采样参数。统一操作数上限不等于同样推理预算，要同时报告模型、图像、查询、维护和时间成本。缓存命中字段缺失应标为未知。

加入无外部变化、无关变化和要求合法取代等负控制，避免通过“始终重验/拒绝”刷低危险率。内核/环境错误、查询绑定错误、证据失效漏判、要求误读与普通建模失败分别归因；不得把所有失败都归咎于记忆。

## 9. 指标、统计与推进门槛

### 9.1 不用单一相似度代替工程验收

| 指标 | 定义及解释 |
| --- | --- |
| 阶段成功率 | 当前目标和仍有效保护项同时满足的阶段数 / 全部预定阶段数；合理冲突处置单列 |
| 整链成功率 | 全部要求阶段均通过的项目链比例；与阶段分数同时报告 |
| 首个严重错误位置 | 每条链首次发生保护项损伤、危险旧判断使用或错误提交的阶段；未发生者作截尾记录 |
| 旧证据误用率 | 真正失效却作为当前行动依据的旧命题 / 被用于行动的可核验旧命题；分母为零单列 |
| 有效证据保留率 | 当前任务需要且仍成立的历史命题中，被正确保留并可用的比例 |
| 重验/未知/覆盖 | 分别统计精确重验量、未知比例和支持范围，避免全部遗忘被误判成优秀记忆 |
| 恢复与总体代价 | 错误后恢复步数、重复操作、模型输入/输出与图像费用、内核/维护时间、端到端延迟 |

真值以独立查询/验收为准，不能直接采用候选方法自己的证书或 LLM 自评分。正确冲突提示、过度拒绝、目标未完成和不受支持类型要分别统计。通孔/间隙等要求优先用几何量验证；主观意图仍需要盲评或人工核验。

### 9.2 统计与因果解释

按同一项目/事件序列做成对比较，统计不确定性以项目为单位聚类或 bootstrap；同一项目中的多个阶段不是独立样本。预注册主指标、预算、缺失处理和停止规则，探索性分析另列。开发集选择规则后，在冻结测试集上一次性核验。

链越长，全链成功率会自然下降。例如每阶段成功概率固定为 0.95 且独立，50 阶段全成功概率也只有约 7.7%。这是数学说明，不是模型实验结果；不能仅凭长链退化证明记忆失效。必须结合成对控制和具体错误轨迹。

### 9.3 拟定的推进与停止条件

预实验要求受控支持范围内未发现错误准入，同时保留足够有效证据；争取相对最强几何基线减少至少 30% 精确查询，再检查端到端质量-费用/延迟是否仍有实质改善。**30% 是事先讨论的工程决策阈值，不是已测结果或论文承诺。** 有限集零错误也不是普遍安全证明。

若最新状态或空间依赖基线已经足够、真实续作中问题罕见、保守规则导致几乎全重验、维护成本吞掉节省，或换项目/模型后收益消失，应停止复杂机制。仅有内核毫秒级收益而不改善可靠性或总体代价，不足以支撑宽泛的 AI-CAD 方法结论。

## 10. 如何开始、阶段交付与预期结果

### 10.1 建议的六阶段节奏

下表是按约六周组织的研究顺序，不是交付日期承诺。每阶段以证据决定是否进入下一阶段，必要时收缩范围或回退。

| 阶段 | 主要工作 | 完成标志 |
| --- | --- | --- |
| 第 1 阶段：协议与真值 | 冻结任务定义、可见权限、事件/要求生命周期和错误分类；选小装配场景 | 有可运行最小任务包、解析校准和独立验收说明 |
| 第 2 阶段：问题诊断 | 构建拟定的 120 检查点；运行最新状态、粗粒度和空间强基线 | 能定位失效模式及不确定性，确认值得研究的差距 |
| 第 3 阶段：最小机制 | 实现三类查询证据、保守依赖/guard、未知回退和上下文重建 | 离线与新鲜内核结果一致；比较维护开销而非只看命中率 |
| 第 4 阶段：闭环续作 | 接一个 harness，运行短项目链，再按结果扩展长度 | 无标准快照覆盖，逐阶段目标/保护项与费用可追溯 |
| 第 5 阶段：验证与消融 | 冻结测试、第二模型/harness、必要 ACIS 迁移与压力条件 | 主指标、消融和强基线对照一致，失败案例完整保留 |
| 第 6 阶段：论文与发布 | 整理数据卡、复现脚本、图表、相关工作和局限 | 形成可审阅论文初稿与可复现研究包；不保证录用 |

### 10.2 第一个工作周期的具体动作

1. 写出三种示例任务包与当前要求清单，定义一个合法要求取代和一个新增障碍事件。
2. 确立统一查询返回：版本、单位、参考系、对象绑定和失败/未知原因；先不加入学习策略。
3. 对解析尺寸、最小距离和区域干涉校准独立评价器；制造已知错误，确认它确实会拒绝。
4. 先跑最新状态全重验和空间依赖基线，保存成对轨迹；确认差距后再设计复杂机制。
5. 确定测试划分、指标与新增模型预算。现有 M5/24 GB 环境用于内核与诊断，付费 API 另行核对预算；本报告没有新增模型调用。

### 10.3 期望产出与主要风险

期望形成三类成果：**可复现的持续编辑协议与数据**；**有明确适用范围、可回退的证据维护方法**；**解释何种变化使现有系统失效、何种情况下简单基线已经足够的实证分析**。论文叙事应由问题、证据和机制连接起来，而非仅展示新架构图。

主要风险是近邻机制已足够、任务过度合成、绑定/评价器错误、内核差异和维护成本。对应措施是先跑强基线、引入独立场景与人工合理性审核、交叉核验、固定主后端并另做迁移实验、完整计费。不要因沉没成本持续包装没有额外收益的机制。

**今天的结束点**：题目与研究边界已确定，工程准备可用；明天应从协议和强基线诊断开始。benchmark、方法效果和发表新颖性仍是研究要检验的结果，不是本报告已证明的结论。
