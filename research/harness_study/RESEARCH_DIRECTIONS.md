# InferraCAD：从闭环中的信息与决策环节寻找研究问题

文献检索截至 2026-10-25。这是可证伪的研究计划，不是已验证的创新声明。当前三框架实验主要用于建立可运行的比较环境；小样本、单模型、单次运行不能证明整个领域存在同一个缺陷。

## 优先候选：按待验证的主张选择观测，而非每一步重复渲染

闭环常被写成“生成/编辑 → 执行 → 看结果 → 修正”。其中容易被忽略的是：**这次观测到底能否区分正确状态与错误状态？** 增加图片、换更强的反思模型，并不自动增加可用证据。

本地代码有一个具体可检验的例子：AgenticCADedit 的 `src/utils/cadquery_rendering.py` 在每次渲染时独立调用 `view.FitAll()`。对形状做整体平移或等比缩放后，自动居中和缩放会消除部分变化信号。对于只观察这些图片的判定器，两个几何状态可能几乎不可区分。这是观测通道的信息损失；不能据此声称完整系统无法解决，因为它还可以读取几何数值。

本轮对全部 VLM 代理通过结果的后验审计还发现：两个输出重新生成了明显不同尺寸或结构的零件，却被判为通过。原始评分保留，不能据此宣布真实语义优胜者。这说明判断当前候选的外观与尺寸，还需要与编辑前的几何基准对应；这项观察同样不是已证成的新颖性。

一个更值得研究的模块是 **任务主张到观测需求的映射**：

- “放大两倍”：需要共享尺度的前后视图，或对应尺寸的比值。
- “沿 X 移动 12”：需要世界坐标和单位基准；独立自动居中的图片不够。
- “通孔而非盲孔”：外观相近时需要剖面、射线穿透或拓扑连通性检查。
- “只改这个孔”：需要局部变化证据与非目标区域的保留证据。

在每步编辑前后，系统维护少量待判定主张，选择能区分竞争解释的工具：同相机前后对照、局部放大、剖切、长度/半径/体积/连通性查询。选择应同时考虑费用、延迟和判别力；观测不能判定时允许返回“不知道”，避免把相似图像当成完成证据。

### 最近工作与边界

[AgenticCADedit](https://arxiv.org/abs/2609.29621) 已有检查、选择高亮、渲染和撤销。因此“加入视觉反馈/检查工具”不是新贡献。

[SightCAD](https://arxiv.org/abs/2610.11954) 已学习预算约束下的可行视角选择，主要任务是遮挡条件下的参数化 CAD 重建。[OmniMech](https://arxiv.org/abs/2608.05539) 也包含自适应视角、测量与工具迭代。因此“主动选择视角”本身也不足以声称创新。候选区别在于：**针对已有精确 B-Rep 的编辑主张，跨视觉与数值工具选择最小充分证据，特别处理前后变化的尺度、坐标与版本对应。** 是否足够新，仍需扩大文献和代码核查。

### 最小消融设计

在冻结的任务、模型、编辑器与执行预算上比较：A 原始反馈；B 仅增加相同数量的随机视图；C 固定世界相机的前后对照；D 精确数值检查；E 根据当前主张选择 C/D/剖面。每种设置匹配图片数量、像素和模型输入预算；额外内核调用单独记费。另做 C+同等长度无关文字控制，排除“只是多了上下文”。

任务至少包括尺度/位置、孔深/连通、装配相对关系三类，并保留不需要新观测的普通任务作负控制。以人工验收、尺寸误差、错误宣告完成率、恢复次数、费用为结果。按模型/零件划分开发集和测试集，阈值在开发集确定；报告多种子和配对区间。

**否证条件：** 如果等预算随机观测同样有效，或精确几何检查已经解释全部增益，或者效果只出现在人为构造的缩放玩具任务上，就不能主张通用的观测规划贡献。本轮附带的 36 次判定诊断只检查信息机制，不代表端到端编辑效果已经提升。

## 候选二：在执行前写出可检查的“预期变化”

目前的失败日志往往只告诉 agent “执行成功/失败”。即使成功，它是否实现了原本的几何目的，仍需要重新推断。可以让每个行动附带预测：应改变哪个实体/区域、哪些量应变化、哪些量应保持、预计新增或减少多少连通体。执行后把预测与真实变化比较，并把反例定位到区域，而不是只返回全局图片。

这可能改善错误归因：区分意图理解错、选错面/边、参数错误、内核失败与附带破坏。预测必须绑定任务要求，不能让 agent 自己写一个宽松检查再宣布通过。

[TraceCAD](https://arxiv.org/abs/2608.03062) 已研究持续的需求/执行证据、局部修复与保留检查，[CADSmith](https://arxiv.org/abs/2603.26512) 已结合内核几何验证与 VLM 判断。这里潜在的增量应是：面向没有生成代码/建模历史的导入 B-Rep，显式建模行动前的变化预测、执行后的差分反例与跨版本实体对应，而不是把“保存日志”重新命名。

消融至少包括普通循环、同等长度自由思考、结构化预测但不检查、预测+检查、预测+定位反例。检查恢复率和无关区域变化，并把预测错误单独计数。如果只增加思考 token 就有同样效果，应否定这个机制解释。

## 候选三：把“继续操作/获取证据/结束”作为一个联合决策

能导出 STEP 与能交付用户需要的编辑是两回事。模型自行发出 finish，缺少证据时可能过早结束；只是不停修复，也可能越改越坏、消耗预算。

可以学习或校准一个决策：当前证据是否足够交付；再测量一次是否有价值；哪一种额外操作值得费用。评估应同时报告完成率、错误交付率、拒答/需人工处理比例与成本，画风险—覆盖率曲线。使用从未参与生成的人工标注做校准，避免同一模型既生成又给自己打分。[ProCAD](https://arxiv.org/abs/2602.03045) 已研究主动澄清，因此普通“遇到歧义就问人”也不是足够的新贡献。

消融：固定轮数结束、模型自主结束、只检查实体有效性、静态全量检查、预算感知的证据选择与结束策略。特别报告“剩余预算相同”的比较，防止更保守的方法仅靠少交付显得更安全。

## DBCAD 的可利用基础，以及不应夸大的部分

DBCAD 已有 SAT 内容寻址、精确 ACIS 操作、不可变版本与实体图投影，适合记录前后差分、冻结观测基准和实现可回退试验。ACIS 本身不是算法创新；把现有工具换个名字、加一层提示词，也不足以支撑论文。

[CADIR](https://arxiv.org/abs/2608.00891) 已有构造图、几何签名匹配和跨系统编辑。若继续“无历史 B-Rep 的保留验证”方向，最近的对照必须包含 CADIR/TraceCAD，而不只是本轮三个 harness；如果无法迁移其代码，应明确实现层次与差异。

另一个工程基线是 [AgentCAD](https://github.com/Getopir/AgentCAD)，已有受控工具、事务和诊断设计。其工程功能也不能被当作我们的独占创新。

值得建立的具体问题是：**在固定预算下，补足正确的观测证据，能否比增加生成/反思轮数更有效地提高真实编辑验收率？** 先做反例与消融，再决定是否值得训练、扩展数据或投稿。当前结果只能帮助挑选这个问题，不能保证它成立，更不能保证发表。
